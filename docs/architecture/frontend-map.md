## Request and persistence boundaries

- Server reads call `lib/server-api.ts`. It forwards `shipping_session` and `shipping_workspace`, disables the fetch cache, deduplicates identical reads within a server render with React `cache`, redirects missing/expired sessions, and routes 404/422 to Next's not-found boundary.
- Browser JSON and multipart actions use `lib/client-api.ts` through the same-origin `/api/v1/:path*` rewrite in `next.config.ts`. Document previews, final B/L confirmation and download links have purpose-specific fetch or link behavior. The frontend has no direct database connection.
- `apps/api/src/shipping_ai/main.py` mounts the routers under `/api/v1`. `core/auth.py` validates a hashed PostgreSQL staff session and binds workspace membership. `core/access.py` scopes company, intake, master list and run queries. Mutation routes generally verify the configured browser origin. SQLAlchemy models and Alembic revisions own persistent data. Fleet is workspace scoped.
- Intake archives validated PDF/Excel originals by SHA-256 in private local storage, links provenance and revisions via `Document` and `IncomingMessage`, and commits an `AutomationRun` with the intake transaction. Celery beat schedules the Redis-backed drain. The worker claims PostgreSQL rows and persists extraction, review snapshots, activity and status. Approvals lock and validate against the current revision, persist reviewed objects and can generate an XLSX permit into PostgreSQL. External connector delivery and permit release keep their existing authorization and audit paths.

### Connector management

- Gmail connects with POST `/integrations/gmail/connect`. Google returns to GET `/integrations/gmail/callback`. POST `/integrations/gmail/settings` and `/integrations/gmail/disconnect` manage `GmailConnection`. OAuth state uses Redis. Gmail sync archives authorized arrivals through the intake pipeline.
- Folder management uses POST `/integrations/folders`, `/integrations/folders/{source}/settings` and `/integrations/folders/{source}/pairing`. `integrations/folders.py` writes `FolderSource`, creates temporary Redis pairing tokens and separately serves the folder agent. The desktop helper link serves the existing public ZIP.
- Telegram uses POST `/integrations/telegram/pairing-token`, `/integrations/telegram/sync` and `/integrations/telegram/recipients`, and POST `/integrations/telegram/recipients/{recipient}/unlink`. `integrations/routes.py` uses Redis for pairing and persists `TelegramRecipient` records. Webhook/agent endpoints are backend entry points outside the page graph.

## Refactor sequence

1. Relocate fleet, workspace, authentication, intake, integrations, automation and shared UI. Remove verified dead entry points and add fleet coverage.
2. Move the review and verification workflow and CDC UI, share the server review entry between the two routes and remove orphaned alternate review panels.
3. Re-resolve imports and verify route, styling, API and persistence boundaries on the final tree.

Run TypeScript, ESLint, the production build and relevant tests for each batch. Browser verification uses a disposable PostgreSQL database, Redis, FastAPI, Celery worker and beat, and a production Next.js build.
